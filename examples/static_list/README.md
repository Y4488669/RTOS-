# 静态链表模板:没有 malloc 怎么建链表

> 给你解决"一直用 `malloc`/`new` 建链表,到了裸机 RTOS 突然没堆可用"的难受。
> 这个目录专门放平时我帮你生成的示例代码,不参与 STM32 固件编译。

## 一、为什么内核里不用 malloc / new

| 原因 | 说明 |
|---|---|
| **确定性** | `malloc` 的耗时不定,可能触发系统调用/锁,实时系统要求"最坏情况有界" |
| **碎片化** | 裸机内存小,长期分配/释放会把堆切成碎块,最终分配失败 |
| **中断安全** | 中断上下文里不能调不可重入的 `malloc` |
| **生命周期** | 任务、栈、队列这些内核对象**和程序同生共死**,自始存在,不需要"动态创建再释放" |
| **内存量级** | STM32F407 总共 128K RAM,内核对象本就该静态占位,把堆留给真正的数据 |

> 即便以后给内核加动态内存(`heap_4` 那种),也强烈建议:**任务控制块和栈静态声明,只有消息、数据块才走堆。**

## 二、核心思维转变:从"造节点"到"串对象"

**你以前的写法(malloc):**

```
node = malloc(...)   ← 先造一个节点
填数据 → 把 node 挂进链表 → 用完 free(node) → 管内存、防泄漏、防悬垂
```

**静态写法:**

```
对象(任务)本来就存在  ← 全局数组/静态声明,编译期已占内存
对象里内嵌一个"链表节点"成员
链表只是把各个对象里的节点"串起来"
不用 free —— 因为它本来就"永远活着"
```

打个比方:
- **malloc 版** = 买一根绳,串一颗珠子,再买一根绳,串一颗珠子……绳子珠子一起管理。
- **静态版** = 每颗珠子自己带一个环,你只决定环和环怎么扣,珠子你永远不扔。

**注意:算法逻辑一模一样**(遍历、按优先级插入、摘除、取头),变的只有"节点内存从哪来"。

## 五、怎么接回你的 RTOS(下一步 M2)

你现在的 `RTOS/` 里有两处要替换:

1. **`kernel.c` 的固定双槽** —— `static TCB *task_table[2]` 和 `select_next_stask()` 的 `0↔1` 切换
   → 换成 `List_t ready_queue;` + `List_PopHead(&ready_queue)`(以及将来按优先级插入)。

2. **`list.h` 里现在的设计** —— 你当前把"节点"和"链表"混成了一个结构体,且 `pxNext/pxPrevious` 指向 `List` 自身,这会造成递归嵌套。
   → 建议按本模板拆成"节点内嵌 + 哨兵链表"两层的标准形态。

3. **`TCB` 定义重复** —— `TCB` 同时在 `kernel.h` 和 `list.h` 里定义,后续会互相冲突。
   → 把 `TCB` 放回 `kernel.h`(或单独的 `tcb.h`),`list.h` 只关心"节点"。

## 六、给进阶者的两个点(先别急,做 M2 时再看)

- **`container_of`**:本模板用 `owner` 指针从节点找回对象(最简单)。更省内存的进阶做法是不存 `owner`,用 `(char*)item - offsetof(Task_t, xItem)` 反推——FreeRTOS 用前者,Linux 内核链表用后者。
- **`pxContainer`**:节点记住"自己在哪个链表",`List_Remove` 就不需要调用方传链表,删除复杂度 O(1) 且不会删错。
